## 3. Опис проєкту

Проєкт реалізує клас `LogAnalyzer`, що аналізує записи HTTP-сервера у форматі **Common Log Format (CLF)**. Програма вміє 
знаходити унікальні IP-адреси та визначати IP-адреси, які найчастіше зустрічаються у коректних записах журналу.

Обробка виконується засобами стандартної бібліотеки Java. Сторонні бібліотеки для колекцій не використовуються.

### 3.1. Формат вхідних даних

Приклад запису журналу:

```text
127.0.0.1 - alice [01/May/2025:07:20:10 +0000] "GET /index.html HTTP/1.1" 200 9481
```

Основні частини запису:

| Поле | Приклад | Значення |
| --- | --- | --- |
| IP-адреса | `127.0.0.1` | Адреса клієнта |
| Ідентифікатор | `-` | Ідентифікатор клієнта (може бути відсутній) |
| Користувач | `alice` | Ім'я користувача |
| Дата та час | `[01/May/2025:07:20:10 +0000]` | Час звернення із часовою зоною |
| HTTP-запит | `"GET /index.html HTTP/1.1"` | Метод, ресурс і версія протоколу |
| Статус | `200` | Код HTTP-відповіді |
| Розмір | `9481` | Кількість переданих байтів |

Рядки, які не відповідають передбаченому формату, ігноруються під час аналізу.

## 4. Реалізовані методи

Основний клас розташований у пакеті `ua.kpi.comsys.collections`:

```java
public class LogAnalyzer {
    public Set<String> getUniqueIps(List<String> logLines);
    public List<String> getTopIps(List<String> logLines, int topN);
}
```

### `getUniqueIps(List<String> logLines)`

Повертає множину (`Set<String>`) **унікальних IP-адрес** із коректних лог-записів.

Алгоритм:

1. Перевіряє, що `logLines` не дорівнює `null`.
2. Послідовно аналізує кожен рядок та відкидає некоректні записи.
3. Витягує IP-адресу і додає її до множини без дублювання.
4. Повертає результат.

Якщо вхідний список порожній або не містить жодного коректного запису, повертається порожня множина.

### `getTopIps(List<String> logLines, int topN)`

Повертає список (`List<String>`) з **не більш ніж `topN` найчастіших IP-адрес**.

Алгоритм:

1. Перевіряє вхідні параметри.
2. Підраховує кількість появ кожної IP-адреси в коректних записах за допомогою `Map<String, Integer>`.
3. Сортує IP-адреси за **спаданням частоти**.
4. Якщо частоти однакові, застосовує **лексикографічне сортування за зростанням**.
5. Повертає перші `topN` елементів або всі наявні адреси, якщо їх менше.

**Приклад tie-breaking:** якщо `10.0.0.5` і `192.168.1.10` зустрічаються однакову кількість разів, першою у списку буде 
`10.0.0.5`.

### Обробка граничних випадків

| Умова | Результат |
| --- | --- |
| `logLines == null` в будь-якому методі | `IllegalArgumentException("logLines cannot be null")` |
| `topN <= 0` в `getTopIps()` | `IllegalArgumentException("topN must be greater than 0")` |
| Порожній список логів | Порожній `Set` або `List` |
| Некоректний рядок журналу | Ігнорується |
| `topN` більше за кількість унікальних IP | Повертаються всі наявні IP в потрібному порядку |
| Однакова кількість звернень | Лексикографічне сортування IP |

## 5. Приклад роботи програми

Вхідні дані:

```text
127.0.0.1 - alice [01/May/2025:07:20:10 +0000] "GET /index.html HTTP/1.1" 200 9481
192.168.1.10 - bob [01/May/2025:07:21:10 +0000] "GET /home HTTP/1.1" 200 1200
127.0.0.1 - alice [01/May/2025:07:22:10 +0000] "POST /login HTTP/1.1" 200 500
```

При запуску демонстраційного класу `Main` очікується вивід:

```text
Unique IPs: [127.0.0.1, 192.168.1.10]
Top 2 IPs: [127.0.0.1, 192.168.1.10]
```

IP `127.0.0.1` трапляється **двічі**, `192.168.1.10` — **один раз**, тому перша адреса очолює рейтинг.

## 8. Запуск проєкту

### Передумови

- Встановлений **JDK 21**.
- IntelliJ IDEA або термінал.
- Наявні файли Gradle Wrapper (`gradlew`, `gradle/wrapper/`).

### Демонстраційний запуск

1. Відкрити папку проєкту `lab2` в IntelliJ IDEA.
2. Дочекатися синхронізації Gradle.
3. Відкрити `src/main/java/ua/kpi/comsys/collections/Main.java`.
4. Запустити метод `main()` через **Run**.

### Запуск юніт-тестів

У корені проєкту виконати:

```bash
./gradlew test
```

Або запустити `LogAnalyzerTest` безпосередньо через IntelliJ IDEA.

### Повна збірка

```bash
./gradlew clean build
```

У разі успішного виконання Gradle показує повідомлення `BUILD SUCCESSFUL`.

Для macOS/Linux за відсутності дозволу на запуск Wrapper:

```bash
chmod +x gradlew
```

## 9. Юніт-тестування

Тести `LogAnalyzerTest` написані з використанням **JUnit 5**. Тестові дані та очікувані значення можуть бути згруповані 
у вкладеному класі `TestResources`.

Передбачені перевірки:

1. Отримання множини унікальних IP-адрес.
2. Сортування найчастіших IP за кількістю звернень.
3. Лексикографічний порядок за однакової частоти.
4. Випадок, коли `topN` перевищує кількість унікальних адрес.
5. Обробка порожнього списку.
6. Ігнорування некоректно сформованих логів.
7. Обробка `null`-елементів у списку.
8. Розпізнавання IPv6-адрес у передбаченому форматі.
9. Виняток для `null` у `getUniqueIps()`.
10. Виняток для `null` у `getTopIps()`.
11. Виняток для нульового або від'ємного `topN`.

Фактичний результат виконання тестів перевіряється командами `./gradlew test` і `./gradlew build`.

## 10. Підсумок

У межах лабораторної роботи реалізовано аналізатор серверних логів із використанням стандартних колекцій Java. 
Розроблено алгоритми виділення унікальних IP-адрес, підрахунку звернень, сортування результатів та обробки некоректних 
даних. Для збірки проєкту передбачено Gradle з Version Catalog, а для перевірки поведінки — модульні тести JUnit 5.
